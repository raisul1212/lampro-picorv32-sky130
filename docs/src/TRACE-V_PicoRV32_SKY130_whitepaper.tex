\textit{TRACE-V: Traceable RISC-V --- AI-built, Checked, Evidenced.} The release is published at \url{https://github.com/raisul1212/trace-v} for non-commercial academic instruction and research.

TRACE-V is a worked example of block-level implementation and verification. Reported signoff is limited to the stated checks, constraints and conditions. It is not fab-ready.

Release v2.0.2 contains two implementations of the same design, introduced in v2.0. The same RTL and the same constraint file were implemented by a commercial flow (Cadence Genus and Innovus) and by an open flow (Yosys and OpenROAD in LibreLane), and both builds are verified with the same open-source scripts. The commercial circuit artifacts originate in release v1.0.1; the verification scripts and the documentation were corrected in v2.0.2. Release v1.0.1 replaced the 8 ns route of v1.0 with an 8.25 ns route, which has a wider setup margin at the slow corner; the 8 ns release remains available at tag v1.0.

\section*{Abstract}
\begin{itemize}
\item \textbf{Commercial build (v1.0.1).} The PicoRV32 RV32I core was taken from RTL to block-level signoff on SkyWater sky130A at 8.25 ns (about 121 MHz). The requirements were set and the decisions were approved by the designer; implementation, verification, debugging and fixes were carried out by agentic AI on a commercial implementation flow. The routed block has 8,273 cells in a 357.42 $\times$ 355.64 \textmu m die.
\item Setup slack is +0.180 / +2.388 / +2.957 ns and hold slack is +0.716 / +0.214 / +0.034 ns at ss / tt / ff, after 0.25 ns clock uncertainty. Slew, capacitance and fanout violations are 0 at all three corners.
\item DRC (Magic and KLayout), antenna and LVS are clean, and both LEC steps are equivalent. The post-layout functional simulation of the golden program, with partial SDF timing (Icarus Verilog), passes at 8.25 ns and the 4.125 ns control fails; the CVC timing-check simulation released with v2.0.2 passes at 8.25 ns with 0 timing violations; a re-run in Xcelium with flop timing checks enforced also passes at 8.25 ns with 0 violations.

\item Six defects that each passed a tool's own report were found and corrected by agentic AI (section~\ref{sec:caught}). Signoff is at nominal RC (section~\ref{sec:rc}).
\item \textbf{Open build (v2.0).} The same RTL, under the byte-identical constraint file, was implemented with Yosys and OpenROAD in LibreLane 3.0.14, with private modifications to OpenROAD that are not published (section~\ref{sec:openimpl}). \item In the shipped OpenSTA run, setup slack is +0.129 / +2.028 / +2.706 ns and hold slack is +0.744 / +0.235 / +0.054 ns at ss / tt / ff, with 0 slew, capacitance and fanout violations. DRC (Magic and KLayout), antenna and LVS are clean. Functional simulation with partial SDF timing (Icarus Verilog) passes at 8.25 ns, and so does Xcelium with 0 timing violations; both controls fail. DRC was run with two independent decks, LVS was run against the routed netlist, and logic equivalence was checked at both synthesis and routing. Post-layout gate-level simulation was run with flop timing checks, and static IR was analyzed. The failure handling of the verify scripts is tested offline. Reported figures cite released evidence files with checksums; figures without a located report are withdrawn (see \sk{docs/v2.0.2-errata.md}). \section*{Background: PicoRV32}
PicoRV32 is a CPU core by Claire Xenia Wolf that implements the RISC-V RV32IMC instruction set. It can be configured as RV32E, RV32I, RV32IC, RV32IM or RV32IMC [1]. It is size-optimized, at 750--2,000 LUTs and 250--450 MHz on Xilinx 7-series FPGAs, and is intended mainly as an auxiliary processor in FPGA and ASIC designs [1]. Its average CPI is about 4, depending on the instruction mix. It is released under the ISC license [1]. The FPGA frequency, LUT count and CPI figures and the instruction-count background below are externally sourced background; they are outside this repository's evidence and reproduction guarantee, and they are not measurements of this ASIC package.

It is a general-purpose CPU. RV32I is RISC-V's base 32-bit integer instruction set: 40 distinct instructions covering integer arithmetic, logic, shifts, compares, loads, stores, branches, jumps and system [2]. M (multiply/divide) and C (compressed) are optional extensions [2].

This build uses PicoRV32's default parameters, unchanged [1]:
\begin{itemize}
\item RV32I with all 32 registers and the cycle and instruction counters;
\item no multiply/divide, no compressed instructions, no interrupts and no co-processor interface;
\item a non-barrel shifter;
\item traps on misaligned accesses and illegal instructions.
\end{itemize}

The memory interface works as follows: the core asserts \sk{mem\_valid} and holds it until the memory asserts \sk{mem\_ready}. An optional look-ahead interface (\sk{mem\_la\_*}) announces a transfer one cycle early [1].

The process is SkyWater SKY130, an open-source 130 nm PDK; this design uses the \sk{sky130\_fd\_sc\_hd} standard-cell library [3].

\section{Flow and signoff bar}
Implementation and timing signoff of the v1.0.1 build use a commercial flow. Cadence Genus does synthesis, Innovus does place and route, Tempus produces timing and the SDF, Conformal checks logic equivalence, and Voltus computes IR drop.

Physical signoff uses open checkers, so that anyone can re-verify the layout without the commercial tools: Magic DRC, KLayout DRC with the sky130A\_mr deck, Magic antenna check, LVS with Magic and Netgen, and functional gate-level simulation in Icarus Verilog with partial SDF timing. Icarus Verilog applies SDF path delays only in part (interconnect annotations fail for some entries) and does not evaluate flop timing checks, so the simulation is repeated with the SDF timing checks enforced, in Cadence Xcelium and in the open-source CVC simulator (section 3).

The signoff bar was set once by the designer, and the work was carried out against it by agentic AI without renegotiation per run:
\begin{itemize}
\item 0.25 ns clock uncertainty at ss, tt and ff, included in both setup and hold.
\item DRC clean in two independent decks.
\item Max transition, max capacitance and max fanout violations at 0.
\item Gate-level simulation and both LEC steps pass.
\item Static IR drop within budget, 80 mV on each rail (5\% of 1.6 V).
\end{itemize}

The open build of v2.0 was checked against the same bar (sections~\ref{sec:openimpl} and \ref{sec:openverify}).

The workload for simulation is a hand-assembled RV32I golden program of 9 instructions that sums 1 to 10 and stores 55.

\subsection*{Modifications inside the open-source tools}
Implementation used OpenROAD with private modifications that are not published. Every check an outsider runs uses unmodified open-source tools. The modifications are in four places.
\begin{enumerate}
\item \textbf{OpenROAD Resizer (\sk{rsz}): electrical repair and rebuffering.} After routing, repair uses the extracted parasitics, including zero-length shunt capacitances, in place of an estimate that had under-counted wire load by 2.2 to 2.4 times on the nets of a parasitic probe (a development record that is not released here). Driver sizing uses the selected corner's model and the SDC slew limit, and fanout headroom accounts for antenna-diode loads.
\item \textbf{OpenSTA inside OpenROAD: parasitics and SDC.} The SPEF reader and the parasitic store give the Resizer the extracted RC network in a form its buffering model can use, and constraint checks ignore empty exception entries.
\item \textbf{OpenROAD PSM: static IR.} Voltage sources can be placed on a power pin's own routing layer as well as on the top layer. With this change, the PSM result on the commercial layout is 12.09 / 12.07 mV against the Voltus values 11.0 / 11.58 mV quoted in the comparison record; this does not establish general agreement between the tools.
\item \textbf{LibreLane: flow integration.} A post-route loop repairs electrical, setup and hold violations against freshly extracted parasitics, the flow exits with failure when a stated setup target is missed, and unchanged detailed wires are preserved.
\end{enumerate}
Yosys and ABC, Magic, KLayout, Netgen and Icarus Verilog were not modified. The antenna repair of the final layout uses a stock LibreLane step.

\subsection*{Equivalence}
Conformal LEC 24.10 was used for both steps.
\begin{itemize}
\item \textbf{RTL $\to$ Yosys netlist: equivalent.} There are 1,959 compare points (1,862 compared points and 97 reported equivalences), with 0 non-equivalent, 0 aborted and 0 unknown (\sk{reports/conformal/}).
\item \textbf{Yosys netlist $\to$ routed netlist: equivalent.} There are 1,904 compare points, with 0 non-equivalent and 0 aborted.
\end{itemize}
The RTL-to-netlist comparison required three steps:
\begin{enumerate}
\item flip-flop instances were renamed after their RTL registers, by a script that asserts identical cells and connections;
\item FSM encoding files were given for the two state registers that Yosys re-encoded: \sk{cpu\_state} from 8-bit one-hot to 7-bit one-hot, and \sk{mem\_wordsize} from 2-bit binary to 3-bit one-hot;
\item Conformal setup analysis merged 77 RTL registers (duplicates and registers the default configuration never uses) and treated 5 as constants.
\end{enumerate}
The control is the same comparison without the encoding files, in which 1,246 points are non-equivalent. A stage-1 proof aid without setup analysis (not the shipped design) leaves 1,202. \section{Software developed for this work}\label{sec:software}
The design was implemented and verified by an agentic chip-design framework under the designer's direction. The software developed for it falls into three groups.
\begin{enumerate}
\item \textbf{Modifications inside open-source tools}, the four listed in section~\ref{sec:openimpl}. They are private and not published.
\item \textbf{Adapters of the agentic framework.} An adapter drives one tool step, reads its settings back, refuses a run it cannot verify, and records the result.
\begin{itemize}
\item Used for this release, commercial flow: adapters for Genus synthesis, Innovus place and route, Tempus timing, Voltus static IR and Conformal logic equivalence, behind an evidence registrar that writes each result to a ledger and freezes the run with checksum manifests. The Xcelium simulation ran as a recorded job.
\item Used for this release, open flow: LibreLane runs with recorded configurations and hashes; the Conformal equivalence set-up (flip-flop renaming checked for identical structure, and FSM encoding files); PSM runs with a source-feed control and a weakened-grid control; and the stock-LibreLane ECO diode run.
\item Used for both builds: the verification scripts shipped in each folder's \sk{verify/}.
\item Developed alongside: an open logic-equivalence adapter over Yosys and ABC, whose run on this design is reported only as the negative result in the step-by-step table (586 of 1,864 compare points proven; it did not prove the RTL-to-netlist step); and, not the source of any released number, an open static-IR adapter over OpenROAD PSM and a LibreLane runner and pre-flight plugin that read back every setting.
\end{itemize}
\item \textbf{Evidence handling.} Results were recorded in a ledger and the runs were frozen with checksum manifests (the eight historical manifests are in \sk{commercial/reports/historical\_inventory/}). The failure handling of the verify scripts is tested offline by \sk{tests/test\_verify\_failures.py}. The historical damaged-input controls known from the released reports show the stated responses in those runs; they do not establish that every checker detects every damaged input.
\end{enumerate}

\section{How the platform works}
The requirements were set and the decisions were approved by the designer. Implementation, verification, debugging and fixes were carried out by agentic AI against the signoff bar fixed in section 2. Five properties determine whether the results can be trusted.
\begin{enumerate}
\item \textbf{Numbers cite their source.} Figures cite the run that produced them, and the released evidence files carry provenance records (original and published checksums). A figure for which no report was located is withdrawn, not quoted from memory or from a log summary.
\item \textbf{Historical runs are frozen with checksums.} A reconstruction from eight historical manifests gives 75 entries: 66 in the six implementation and verification sets plus Voltus, and 9 in the Xcelium set. A checksum check of the original files on 16 October 2026 checked 75 entries with 0 mismatches. This is a reconstruction and a new readback, not a total that the project stated at the time, and it counts manifest entries, not distinct contents.
\item \textbf{Key checks have controls.} A check is better trusted after it has been run on a known-bad input. Gate-level simulation fails at 4 ns. The antenna check fails on a frozen known-bad layout. The slew, capacitance and fanout check flags a deliberately overloaded net (a 5 pF load; ss 1 / 0 / 7 and tt, ff 1 / 0 / 5 capacitance, fanout and transition violations). A check that passes every input is treated as broken. These controls show the stated responses in those runs; they do not establish that every checker detects every damaged input.
\item \textbf{Refusal over silence.} A check that cannot run, or whose output cannot be read, is counted as a failure and never as a pass. The scripts clear earlier results, check every tool status and require a fresh single-line verdict; \sk{tests/test\_verify\_failures.py} tests this offline. That test shows that failures are reported as failures, not that a design is correct.
\item \textbf{Independent checkers.} The tool that builds something is always checked by at least one other tool, because a tool checking its own work shares its own blind spots. Innovus builds the layout, but DRC is run by Magic and by KLayout, and LVS by Magic and Netgen. LVS proves the layout matches the routed netlist; Conformal LEC then proves the routed netlist equals Genus' netlist, and Genus' netlist equals the RTL. The result is an unbroken chain of independent checks from the GDS back to the source code. In the open build, OpenROAD builds the layout, and the same open checkers and Conformal verify it.
\end{enumerate}

\section{What the platform caught}\label{sec:caught}
Each of the six defects below, found in the commercial flow, passed its tool's own report: the flow finished and the tool reported success. For each defect, the symptom, how it was found, the root cause and the fix are given. Three practices exposed the defects:
\begin{itemize}
\item \textbf{Read back.} Each result was read back from the design and compared with the requirement.
\item \textbf{Cross-checked.} Results that should agree were compared.
\item \textbf{Controlled.} Key checks were run on a known-bad input.
\end{itemize}

\subsection{The fanout limit was declared and ignored}
\begin{itemize}
\item \textbf{Symptom.} The SDC set a maximum fanout of 10, yet Innovus finished with a fanout violation. The tool's flow completed normally.
\item \textbf{How found.} It was flagged by the slew, capacitance and fanout check. That check is trusted because it flags a deliberately overloaded net (a 5 pF load).
\item \textbf{Root cause.} The router's optimizer and the clock-tree builder each need fanout repair enabled explicitly.
\item \textbf{Fix.} With repair enabled in both, the violation is gone. The clock tree grew and its insertion delay became longer. The numerical before and after figures given in v2.0.1 (violation count, buffer count, insertion delay) are withdrawn because no supporting report was located; the final clock-tree statistics are in \sk{reports/innovus/}.
\end{itemize}


\subsection{STA passed while the gate-level simulation trapped}
\begin{itemize}
\item \textbf{Symptom.} After the fanout fix, setup was met at 8 ns, but the post-layout simulation hit a trap at 8 ns.
\item \textbf{How found.} The failing transaction that occurred earliest in the run was traced by agentic AI. The core misread an instruction it had been given correctly. The interface was then timed: the testbench drives memory on the falling edge, so \sk{mem\_ready} has half a cycle, and the path \sk{mem\_ready} $\to$ \sk{reg\_op1} had negative slack (the earlier value is withdrawn: no report located).
\item \textbf{Root cause.} The constraints set no input or output delays, so STA gave those paths a full cycle. The larger clock tree had made them longer.
\item \textbf{Fix and numbers.} The SDC now states the environment the testbench models, with half-period input and output delays. The simulation then passes at 8 ns, and the input-port hold violations are gone (the earlier slack values are withdrawn: no report located).
\end{itemize}

\subsection{The gate-level simulation was all-X}
\begin{itemize}
\item \textbf{Symptom.} Every simulation failed, at every clock.
\item \textbf{How found.} A zero-delay positive control: the same netlist with no delays must pass, and it did not.
\item \textbf{Root cause.} The power-aware cell models had unconnected supplies, so every output resolved to X.
\item \textbf{Fix.} The simulated netlist now ties every cell's supply and body pins (VPWR, VGND, VPB, VNB) to constant 1 or 0 before simulation. A zero-delay run of the same netlist must pass; that positive control would have caught the all-X result.
\end{itemize}

\subsection{The antenna check could not fail}
\begin{itemize}
\item \textbf{Symptom.} The initial negative control for the antenna check passed. It contained a diode that was not needed, so it was not a violation, and the check had not been shown able to fail.
\item \textbf{Root cause.} The control was not a known-bad input.
\item \textbf{Fix.} It was replaced with a frozen known-bad layout that must fail. The final design has 0 antenna violations.
\end{itemize}

\subsection{A cell excluded from synthesis was re-inserted by place and route}
\begin{itemize}
\item \textbf{Symptom.} KLayout reported one npc.2 violation on the initial 8.25 ns route, while Magic DRC was clean (the spacing values given in v2.0.1 are withdrawn: no report located).
\item \textbf{How found.} The violation was reported by the second, independent DRC deck.
\item \textbf{Root cause.} The cell \sk{sky130\_fd\_sc\_hd\_\_and2\_0} has an NPC edge inside its boundary. It was excluded in Genus, but restructuring in Innovus re-inserted it.
\item \textbf{Fix.} The exclusion is applied in Innovus as well, and a post-route count of excluded cells must be zero.
\end{itemize}

\subsection{An antenna violation remained after the router's repair}
\begin{itemize}
\item \textbf{Symptom.} One net had an antenna ratio of 403.85 against a limit of 400 (the Magic antenna log of a development run, \sk{commercial/reports/development/}).
\item \textbf{How found.} The violation was reported by the open antenna check.
\item \textbf{Root cause.} The router's repair did not bring the net below the limit.
\item \textbf{Fix.} The router's antenna repair setting was changed (the 96\% figure given in v2.0.1 is withdrawn: no report located).
\end{itemize}

\subsection*{Defects found and fixed during the v2.0 work}\label{sec:v2defects}
The same practices were applied to the open flow. Five defects were found and fixed by agentic AI. The numerical values given for these defects in v2.0.1 have no located supporting report except where a file is cited; the others are withdrawn.

\subsubsection*{Constraint mismatch}
\begin{itemize}
\item \textbf{Symptom.} The open flow initially used LibreLane's default SDC, with an I/O delay that differed from the commercial SDC's.
\item \textbf{How found.} The build was timed under the commercial SDC, where it failed ss setup at the input \sk{resetn}.
\item \textbf{Fix.} The build was re-run under the identical SDC, and it closes.
\end{itemize}

\subsubsection*{Fragile closure}
\begin{itemize}
\item \textbf{Symptom.} Before the timing-repair modification, an 8.25 ns closure failed after a small placement change (a change of the wire-length weight).
\item \textbf{Fix.} After the modification, the same perturbation passed.
\end{itemize}

\subsubsection*{Antenna checker disagreement}
\begin{itemize}
\item \textbf{Symptom.} OpenROAD reported 0 antenna violations, and Magic flagged gates on the candidate layouts.
\item \textbf{Root cause.} Magic counts metal3 that reaches a gate through metal4 alone as connected at the metal3 step.
\item \textbf{Evidence.} The net-level ratio comparison and the copy-of-layout experiment behind this diagnosis have no located report and are withdrawn; the diagnosis is the project's explanation, not released evidence.
\item \textbf{Fix.} On the released 45\% layout, two diodes were added with a stock ECO step (the recorded configuration has two ECO diode targets). The shipped DEF holds 494 diodes (\sk{open/reports/development/final-diode-count.json}); this does not establish a 492 to 494 history, and the area and slack changes given in v2.0.1 are withdrawn.
\item \textbf{Alternative considered and not used.} A larger patched mode (its figures are withdrawn: no report located).
\end{itemize}

\subsubsection*{Verification environment}
\begin{itemize}
\item \textbf{Symptom.} With a newer PDK than the pinned one, the diode cells failed LVS.
\item \textbf{Root cause.} LVS and antenna results depend on the PDK version.
\item \textbf{Fix.} The README pins open\_pdks \sk{97d08448}, and the scripts must be run with it.
\end{itemize}

\subsubsection*{Equivalence setup}
\begin{itemize}
\item \textbf{Symptom.} Re-encoded state machines and constant registers defeat a plain key-point comparison: 1,246 non-equivalent points without the FSM encoding files, and 1,202 in the stage-1 plain run, until they were handled (setup record, \sk{open/reports/conformal/}).
\item \textbf{Fix.} The three steps in section~\ref{sec:openverify} (register renaming, FSM encoding files and Conformal setup analysis) resolve it.
\end{itemize}

\section{Limitations}
Packaging, electromigration, metal fill, pad frame, foundry precheck and dynamic IR were outside the scope of this block-level release. Items 1 and 3 apply to the commercial build; items 2 and 4 apply to both builds; items 5 and 6 apply to the open build.
\begin{enumerate}
\item \textbf{Nominal RC.} Signoff is at nominal RC (section~\ref{sec:rc}).
\item \textbf{I/O timing.} I/O timing is set to the testbench's half-cycle memory protocol. The outputs \sk{mem\_la\_read}, \sk{mem\_la\_write}, \sk{mem\_la\_addr[*]}, \sk{mem\_la\_wdata[*]}, \sk{mem\_la\_wstrb[*]}, \sk{pcpi\_valid}, \sk{pcpi\_insn[*]}, \sk{pcpi\_rs1[*]}, \sk{pcpi\_rs2[*]}, \sk{eoi[*]} and \sk{trace\_*} have no output-delay constraints; the PCPI inputs \sk{pcpi\_wr}, \sk{pcpi\_rd[*]}, \sk{pcpi\_wait} and \sk{pcpi\_ready} have 4.125 ns input delays.
\item \textbf{Thin margins.} The margins are ss setup +0.180 ns and ff hold +0.034 ns, after 0.25 ns uncertainty.
\item \textbf{Workload.} The post-layout simulation runs one 9-instruction program covering 6 of 40 RV32I opcodes. Logic equivalence concerns the configured design (default parameters). STA covers the paths constrained by the shipped SDC; it does not establish timing coverage for every interface. CVC times the simulation SDF, which lacks the port-endpoint INTERCONNECT entries, on one workload.
\item \textbf{Open-build IR.} The static IR of the open build comes from OpenROAD PSM with private modifications. No Voltus run exists on the open layout; the PSM method was validated on the commercial layout.
\item \textbf{Commercial checks of the open build.} The equivalence results (Conformal) and the Xcelium timing-checked simulation of the open build use commercial tools and are not regenerated by the open scripts; the timing-checked simulation is reproduced with CVC.
\end{enumerate}
