# TRACE-V v2.0.2: change record

This file records the corrections made in v2.0.2 to the deck, the whitepaper, the README and the
verification package, against the 28 findings of the review of v2.0.1. The deck and whitepaper were
edited in their sources (`docs/src/deck.html`, `docs/src/TRACE-V_PicoRV32_SKY130_whitepaper.tex`) and
both PDFs were rebuilt from them. Page and line references are to the v2.0.1 PDFs.

Each row gives the finding, what was wrong, and what v2.0.2 does. "Applied" means the change is in the
README, the sources and the rebuilt PDFs. A finding marked "open" is not closed in this change.

## Other changes made in the sources

* The deck source gained an `@page` rule (1920 x 1080 px, no margin) so that headless Chrome prints one
  slide per page as in the v2.0.1 PDF; fonts fall back to the system fonts as before (the Google font
  link is blocked at build time, as the v2.0.1 build had no network access to it).
* The SDC comment block (both packages) was corrected; the constraint commands are byte-identical.
  The README gives the new hash prefix `286822dc54798fb9` (v2.0.1: `14469a66864f3bda`). The CVC, area
  and v2.0.1 verification runs were made with the earlier comment block; the commands they read are
  unchanged.

## Provenance notes for the owner

* `docs/src/figs/ir_vpwr_825.png` (VPWR IR map): the producing tool is not recorded in the repository; it was published in v2.0.1 and is kept as it was.
* The CVC logs are output of OSS-CVC 7.00b and the open SKY130 PDK. The SDFs they read are the Tempus-produced and open-flow SDFs already shipped.
* `verify/cvc-local-fixes.patch` modifies OSS-CVC (Tachyon Design Automation, modified Artistic licence); distributing a modified CVC binary would require its source.
* The area run used a copy of the tt liberty and cell LEF from an OpenROAD test directory; an earlier run of the same script on the PDK install gave identical totals (`reports/area/provenance.json`).
