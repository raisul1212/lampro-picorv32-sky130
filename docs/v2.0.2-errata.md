# TRACE-V v2.0.2: change record

This file records the corrections made in v2.0.2 to the deck, the whitepaper, the README and the
verification package, against the 28 findings of the review of v2.0.1. The deck and whitepaper were
edited in their sources (`docs/src/deck.html`, `docs/src/TRACE-V_PicoRV32_SKY130_whitepaper.tex`) and
both PDFs were rebuilt from them. Page and line references are to the v2.0.1 PDFs.

Each row gives the finding, what was wrong, and what v2.0.2 does. "Applied" means the change is in the
README, the sources and the rebuilt PDFs. A finding marked "open" is not closed in this change.

Commercial-tool results (Conformal, Tempus, Innovus, Voltus, Xcelium) were approved for publication under this repository's non-commercial licence. Every released historical evidence file is a scrubbed copy (host, user, licence-server and cluster-path tokens replaced; the one licence-server export in an Xcelium job script removed); each evidence directory carries a `provenance.json` with the original tool, run, size and sha256 and the published size and sha256. The historical hashes do not verify the scrubbed bytes.

## Other changes made in the sources

* The deck source gained an `@page` rule (1920 x 1080 px, no margin) so that headless Chrome prints one
  slide per page as in the v2.0.1 PDF; fonts fall back to the system fonts as before (the Google font
  link is blocked at build time, as the v2.0.1 build had no network access to it).
* The SDC comment block (both packages) was corrected; the constraint commands are byte-identical.
  The README gives the new hash prefix `286822dc54798fb9` (v2.0.1: `14469a66864f3bda`). The CVC, area
  and v2.0.1 verification runs were made with the earlier comment block; the commands they read are
  unchanged.

* The whitepaper figure of fanout repair (bars of 240 to 0, 23 to 174 and 0.46 to 0.95 ns) and the three bar graphics of deck slide 17 were removed with the withdrawn numbers; deck slide 13 now shows the stock rows only, and slides 22 and 24 were rebuilt around the evidenced values (494 diodes, 2 ECO targets; the accounting data).
* After the evidence changes the deck is 29 pages and the whitepaper is 21 pages (it was 19 in the first v2.0.2 build); both PDFs were rebuilt from the sources with the commands below.

* Review fixes after the first v2.0.2 build: (1) `verify/sim_tchk_periods.sh` (both packages) discarded the simulator's exit status, so a crashed simulator (exit 139) that had already printed a passing RESULT and VERDICT was recorded as PASS; a non-zero simulator exit, or a log without RESULT and VERDICT, is now FAIL for that period. (2) `verify/versions.sh` (both packages) masked a Netgen failure behind the pipeline that filters its banner (exit 7 was recorded as PASS); it now fails. Both have new cases in `tests/test_verify_failures.py` (simulator crash, missing RESULT/VERDICT, Netgen failure). The `SHA256SUMS` of both packages were regenerated for these two scripts.
* Wording corrected: deck slide 13 said "every shipped check clean". Every shipped check passes except the open package's CVC negative control, which fails functionally (RESULT timeout) with 0 timing violations and so is not a pass by the control criterion. The README, deck (the open-flow slide and its notes, and the notes of the equivalent-tools slide) and whitepaper said every check an outsider runs uses unmodified tools; CVC is built with `verify/cvc-local-fixes.patch` and the three documents now say so. Slide 5 of the deck was tightened (spacing and a shorter open_pdks note) because its expanded content overlapped the footer on the PDF page; the deck is still 29 pages.
